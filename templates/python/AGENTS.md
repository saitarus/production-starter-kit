## 2. 正規ディレクトリ構成（データ分離・ルート汚染防止）
- `main.py` (または `src/`) - メイン処理スクリプト・エントリーポイント。
- `config/` - 設定ファイル（`settings.json`、YAML 設定等）。本番の `.env` は含めない。
- `data/` - 入出力データ保管ディレクトリ。
  - `data/input/`: 入力元データ（CSV, Excel, 生データ等）。
  - `data/output/`: 処理結果・生成ファイル（スクレイピング結果, レポート等 ※`.gitignore` で除外）。
- `test_scripts/` - テスト・検証用スクリプト群。
- `archive/` - 旧バージョンのスクリプト、過去ログ、移行前コードの退避先。

## 3. ファイル・ディレクトリルール（ルート汚染防止）
- **ルート直下にデータや一時スクリプトを作成しない**:
  - 生成された CSV や画像などの成果物は、ルート直下に置かず必ず `data/output/` 配下に出力すること。
  - テスト・検証用スクリプトはルート直下に置かず、必ず `test_scripts/` 配下に配置すること。
  - 古いスクリプトを「`main_old.py`」「`main_20261011.py`」などとルートに残さず、必ず `archive/` に退避すること。
- **ファイル名は半角英数字に統一**: ファイル名・ディレクトリ名には日本語、全角文字、空白を使用しない。半角英数字、ハイフン（`-`）、アンダースコア（`_`）のみを使用する。
- **機密情報の保護**: API キー、アカウント情報、`.env` は絶対に Git にコミットしない。

## 4. 運用フローと検証義務
1. **仮想環境の利用**: 依存パッケージの導入時は仮想環境（`venv`）を使用し、`pip freeze > requirements.txt` を維持する。
2. **ゴール駆動の検証義務**: 変更後は必ずスクリプトを実行（`python main.py` またはテスト実行）し、正常終了と出力内容を検証してから作業完了とする。
3. **仕様書・変更履歴の一元管理**: 個別の `変更履歴.md` 等は作成・保守せず、規約は本ファイル（`AGENTS.md`）、日々の作業履歴は `Gitコミットメッセージ` に集約する。
