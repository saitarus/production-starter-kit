## 2. 正規ディレクトリ構成（公開分離・多層防御）
- `public/` - 公開 Web フロントエンド（HTML, JS, CSS, 画像アセット, `.htaccess`）。**公開画面の唯一の編集元**。
- `server/` (または `api/`) - バックエンド API コード。Web からの直接アクセスは `.htaccess` で完全遮断。
- `config/` - サービス定義・設定例（`.env.example` 等）。本番の `.env` や秘密情報は含めない。
- `data/` - データベース格納用ディレクトリ（SQLite, JSON 等）。実体データは `.gitignore` で除外。
- `scripts/` - ビルド・配備・運用シェルスクリプト。
- `test_scripts/` - テスト・検証用スクリプト群。
- `archive/` - 旧バージョン、旧コード、旧ドキュメントの退避先。**本番サーバーへ転送しない**。

## 3. ファイル・ディレクトリルール（ルート汚染防止）
- **ルート直下に新しいファイル/ディレクトリを作成しない**: ユーザーからの明示的な指示がない限り、プロジェクトのルート直下に新しいファイルやディレクトリは一切作成してはならない。
- テストスクリプトは必ず `test_scripts/` 配下に配置する。
- **ファイル名は半角英数字に統一**: FTP または本番サーバーへ配置する可能性があるファイル・ディレクトリの名前には、日本語、全角文字、空白を使用しない。名前は半角英数字を基本とし、区切りにはハイフン（`-`）またはアンダースコア（`_`）だけを使用する。
- **機密情報の保護**: API キー、DB 接続情報、`.env` は絶対に Git にコミットしない。

## 4. セキュリティ対策
- **多層防御**: `.htaccess` により、`server/`、`config/`、`data/`、`archive/` への直接 Web アクセスを完全遮断。
- `public/` 階層においても、ドット隠しファイル（`.env`, `.git` 等）および機密拡張子（`.sql`, `.json`, `.sh`, `.yml`, `.md`, `.bak`, `.log` 等）へのアクセスを遮断。

## 5. 運用フローと検証義務
1. **正規の編集元**: `public/`（フロントエンド）、`server/`（API）を直接編集・保守する。
2. **ゴール駆動の検証義務**: コード変更後は必ず構文チェック（Lint）および動作テストを実施し、エラーがないことを検証してから完了とする。
3. **安全な配備**: `archive/`、`test_scripts/`、`.env`、`node_modules` は配備対象外とし、`public/`、`server/`、`config/`、`scripts/` の正規ファイルのみを配備する。
4. **仕様書・変更履歴の一元管理**: 個別の `変更履歴.md` 等は作成・保守せず、規約は本ファイル（`AGENTS.md`）、日々の作業履歴は `Gitコミットメッセージ` に集約する。
